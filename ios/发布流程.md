# iOS 发布流程（从零到用户装上）

iOS 没有「发个安装包让用户下载」这回事。只有三条路，能用的只有前两条：

| 通道 | 能不能给外部用户 | 说明 |
| --- | --- | --- |
| **TestFlight** | 能（公开链接最多 1 万人） | 需要过 Beta 审核，构建 90 天过期，**推荐先用这个** |
| **App Store** | 能（正式上架） | 审核严格，VPN 类还需资质，中国大陆区基本走不通 |
| Ad Hoc / 企业证书 | 不能 | Ad Hoc 要收集每台设备 UDID（100 台上限）；企业证书只能内部员工用，对外分发会被吊销 |

下面按「TestFlight 首发」这条主线写。

---

## 0. 整体流程

```
Apple 开发者账号(¥688/年)
      ↓
开发者后台：建 2 个 App ID + App Group + 开启 Network Extension
      ↓
App Store Connect：创建 App 记录（Bundle ID 一旦上传就锁定）
      ↓
Mac 上 ./build.sh   →  QYVPN.ipa
      ↓
Transporter 上传  →  Apple 处理 10~30 分钟
      ↓
TestFlight 内测（100 人，免审） / 外测（1 万人，过 Beta 审核，生成公开链接）
      ↓
把公开链接填进后台 ios-release  →  下载页出现「加入 TestFlight 内测」
```

---

## 1. 前置准备

**账号**
- Apple Developer Program，个人 ¥688/年；公司账号同样价格但需要 D-U-N-S 编号（免费申请，3~5 个工作日）。
- VPN 类 App 用**公司账号**通过率高得多，个人账号提交这类 App 被拒的案例很多。

**素材（上架才需要，TestFlight 不需要）**
- App 图标：**已内置**（`app/Resources/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png`，
  1024×1024、无透明通道，符合 Apple 要求）。要换图就替换这个文件，保持 1024 正方形、不要圆角、不要 alpha。
- 6.9 英寸 iPhone 截图（至少 3 张）。
- 隐私政策 URL、技术支持 URL（可以是同一页）。
- 审核用的测试账号（VPN 类审核员一定会实际连一次，必须给能用的账号）。

---

## 2. 开发者后台配置（一次性）

1. **Certificates, Identifiers & Profiles → Identifiers**，新建两个 App ID：
   - `cn.qo8.qyvpn.client`（主 App）
   - `cn.qo8.qyvpn.client.tunnel`（扩展，必须是主 App ID 的子标识）
2. 两个 App ID 都勾 **App Groups**，新建 `group.cn.qo8.qyvpn` 并绑定。
3. **只给扩展那个** App ID 勾 **Network Extensions**，Capabilities 里选 **Packet Tunnel Provider**。
   （主 App 不需要，多勾了审核会问用途。）
4. 签名用 Xcode 自动签名即可，`build.sh` 会带 `-allowProvisioningUpdates` 自动生成描述文件。

---

## 3. App Store Connect 创建 App

1. 「我的 App → +」新建，平台选 iOS。
2. Bundle ID 选 `cn.qo8.qyvpn.client`；名称、SKU、语言按实际填。
3. **Bundle ID 一旦上传过构建就不能改**，改名只能新建 App 记录。

---

## 4. 出包

在 Mac 上：

```bash
cd ios
QYVPN_TEAM=你的TeamID QYVPN_VERSION=1.0.0 QYVPN_BUILD=1 ./build.sh
```

产物：`ios/build/export/QYVPN.ipa`

**版本号规则（很重要）**

| | 字段 | 规则 |
| --- | --- | --- |
| 用户看到的版本 | `CFBundleShortVersionString` | `1.0.0` 这种三段式，功能更新才 +1 |
| 上传序号 | `CFBundleVersion`（build） | **每次上传必须比上一次大**，改代码不改功能也要 +1 |

后台 `ios-release` 里填的 `version` + `build` 就是这两个值，客户端拿 build 号比较判断是否提示更新。

---

## 5. 上传

三种方式，任选：

1. **Transporter**（最稳，推荐）：Mac App Store 搜 Transporter，登录 Apple ID，拖入 ipa，交付。
2. **Xcode Organizer**：`Xcode → Window → Organizer → Archives → Distribute App`。
3. 命令行：`xcrun altool --upload-app -f QYVPN.ipa -t ios -u 账号 -p App 专用密码`
   （需要先在 appleid.apple.com 生成 App 专用密码）。

上传后到 App Store Connect → TestFlight 看构建状态，通常 **10~30 分钟**处理完；
如果收到 `ITMS-9xxxx` 邮件，按第 8 节排查。

---

## 6. TestFlight 分发

**内部测试**（最快，适合你自己和同事）
- 最多 100 人，必须是 App Store Connect 里的用户（管理员/开发者/营销角色）。
- **不需要审核**，构建处理完就能装。
- 测试员装 TestFlight App → 收到邀请邮件 → 安装。

**外部测试**（给真实用户）
- 最多 10000 人，需要过一次 **Beta App Review**（通常 1~2 天，比正式审核宽松）。
- 审核通过后在「外部测试 → 公开链接」生成 `https://testflight.apple.com/join/xxxxxxxx`。
- 用户点链接 → 装 TestFlight → 装你的 App。**不需要 Mac、不需要描述文件。**

> 每个构建 **90 天过期**。到期前必须传新构建并让测试员更新，否则 App 打不开。
> 建议把「每 60 天传一次新 build」写进例行维护。

---

## 7. 回填后台（可选）

如果你的服务端实现了 iOS 版本通道（本项目不含服务端，接口定义见下），
填进去之后下载页和 App 内的更新提示才能指向 TestFlight：

```bash
# 接口：POST <你的后台>/api/admin/ios-release
# 字段：version / build / testflight 链接 / notes
curl -X POST https://你的后台/api/admin/ios-release \
  -H 'Content-Type: application/json' \
  -b '会话 Cookie' -H 'X-CSRF-Token: ...' \
  -d '{"version":"1.0.0","build":1,
       "testflight":"https://testflight.apple.com/join/xxxxxxxx",
       "notes":"首个内测版本"}'
```

（管理面板目前没有这个入口，只能调接口；需要的话可以补一个卡片。）

生效后：
- 下载页 `/download` 出现「加入 TestFlight 内测」按钮；
- 已装旧版本的 App 首页会出现「发现新版本 → 前往 TestFlight 更新」。

## 8. 常见被拒 / 上传失败

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ITMS-90032` / 缺图标 | 图标缺失或带 alpha | 本工程已内置合规图标；换图时保持 1024、RGB、无圆角 |
| `ITMS-90717` | 图标有透明通道 | 同上，导出时去掉 alpha |
| `Missing Push/Network Extension entitlement` | 描述文件和 App ID 能力不一致 | 后台勾上 Network Extensions 后，Xcode 里删掉旧描述文件重新下载 |
| `Invalid Bundle - nested bundle` | 扩展的 Bundle ID 不是主 App 子标识 | 必须是 `cn.qo8.qyvpn.client.tunnel` |
| Beta 审核被拒 5.4 | VPN 类需要「由组织提供」+ 说明用途 | 用公司账号，审核备注里写清楚用途、给测试账号 |
| 审核员连不上 | 节点/账号在他们网络环境下不可用 | 准备一个稳定的测试节点，备注里写清步骤 |
| 上传后一直「正在处理」 | 通常只是排队 | 超过 2 小时联系 Apple |

## 9. 能不能上架中国区 App Store

**基本不行。** 依据审核条款 5.4 与中国法规，VPN 类 App 在中国大陆区上架需要提供
主管部门批准文件（工信部相关批复）。没有资质时：

- 中国大陆区会被拒或直接下架；
- 可以先只上架**海外区**（美国区等），同样需要公司账号、隐私政策、说明用途；
- 国内分发就靠 TestFlight 公开链接（这也是很多同类产品的做法），但要注意：
  TestFlight 是测试通道，长期把它当正式分发渠道本身有合规风险。

**这一节不是技术问题，是资质问题，需要你自己判断风险。**

---

## 10. 日常更新循环

1. 改代码 → `QYVPN_BUILD=N+1 ./build.sh`
2. Transporter 上传 → 等处理
3. TestFlight 里把新构建加进测试组（外部测试需要再过一次 Beta 审核）
4. 更新后台 `ios-release` 的 version/build/notes
5. 用户在 App 首页看到更新提示，点进 TestFlight 更新

如果需要「静默强制更新」，iOS 做不到——只能提示，不能像安卓那样自己下载安装。
